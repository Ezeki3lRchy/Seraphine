# common

## Purpose
Shared infrastructure used across the whole app: configuration, logging, theming/icons,
the global signal bus, the self-updater, and general utilities. No UI screens here — this
is the cross-cutting layer everything else imports.

| `update.py` | Platform updaters. Windows `runUpdater(sourceDir)`: writes `updater.ps1` to the config dir and starts it hidden + detached with `-InstallDir` (dir of `sys.executable`; the real layout is `Seraphine.exe` + `filelist.txt` at the root, everything else under `_internal\`, and the app's CWD is `_internal`, so nothing depends on the CWD), `-SourceDir`, `-WaitPid`, `-BackupDir`, `-ResultPath`, `-LockPath`, `-TargetVersion`. The script first takes an exclusive lock file (a second instance exits 7 touching nothing; `runUpdater` does not start one while it is held), waits for that PID, refuses drive-root paths, completes an unfinished restore if an earlier run left a backup whose `backup.meta` fingerprint (SHA-256 of the pre-update and the package `Seraphine.exe`) matches the installed exe — otherwise the backup is foreign and discarded untouched (fails with `restore-failed`/8 if a matching restore cannot complete), then (step 4b, still before anything is backed up or modified) checks the package against the install: with a usable `filemanifest.txt` (first line exactly `#seraphine-manifest 1`; any other first line = no manifest) every entry must match by size + SHA-256 either the package file or, when the package does not ship it, the installed file, and package files the install already has are pruned from the package (never `Seraphine.exe`, `filelist.txt`, `filemanifest.txt`), so a full package and a delta take the same path; the manifest must list exactly the new `filelist.txt`'s files, once each (a duplicate, an extra or an unreadable manifest is `failed:9`); every new-filelist entry no manifest entry covers must be in the package; any mismatch exits 9 (`failed:9`, "package does not match the install; nothing changed", the package left unpruned); a read error is retried (3 attempts, 0.5 s apart; a hash mismatch is final at once); after 4b the merge deadline is reset (logged `deadline:`). It then writes `backup.meta`, prechecks (reparse points, file-vs-dir) and backs up every install file the (pruned) package replaces, robocopy-merges with `/IM` (bounded retries; on failure restores every backed-up file, SHA-256 compare only when a copy fails; the package's `filemanifest.txt` is never merged, so no install-root copy exists), with a manifest verifies every merged file's SHA-256 still inside the merge window (read errors retried as above; a mismatch or lasting read error restores the previous version, exit 4), treats errors after a completed merge as success, then deletes only files in the old `filelist.txt` that the package does not contain (never outside the install dir, never through a reparse point, skipped without a new filelist), writes `<config>/update/result.json` and relaunches whatever is in place; log in `<config>\updater.log` (with `phase manifest|backup|merge|verify|removal: <s> s, ...` timing lines). A package without a manifest runs exactly the pre-manifest path (escape hatch; tested against the v1.4.8 script snapshot). The script carries the line `# seraphine-updater: manifest 1`. After a run, `package/` no longer equals the downloaded asset (4b prunes it). `runUpdaterMac` copies the new .app next to the old one, verifies it, then swaps with a backup (restored on failure). Its single-instance lock is a `mkdir` lock directory under the stage dir holding a three-line record (PID, process identity = `ps -o lstart=` start time, creation time), written without overwriting another updater's record; it is held only while that process is alive with the same identity (the 30-minute age limit applies only to a record without an identity), an incomplete record gets a short grace period, a second instance exits 7 touching nothing, a stale lock is taken over, and a run releases the lock only while the record is still its own (same rule in the script and `_lockDirHeld`). `hdiutil attach`/`detach` are retried, and `detach` runs only for a mount the script made; `updaterRunning(lockPath)` handles both the Windows lock file and the macOS lock directory; `noRelaunch` (like Windows `-NoRelaunch`) is the switch tests use to never open an app afterwards. Not yet run on a real Mac; a darwin-only test runs it in CI |
| `update_stage.py` | Non-UI download (configured proxy) → SHA-256 verify (a sha256 digest is required on every path: a release asset without one is refused before anything is downloaded, and a staged update without one is discarded) → (Windows) extract into `<config>/update/package` (must have `Seraphine.exe` + `filelist.txt`) + `staged.json` marker; reads `result.json` at start-up (failed run → keep stage, offer retry); `applyStagedUpdate` only applies the exact on-disk stage and waits for the updater to start; `BackgroundUpdater` stages in the background only when no game is known to run (unknown / ChampSelect / GameStart / InProgress / Reconnect block it) and reports `onProgress(state, version, cur, total, kind)` (downloading / verifying / extracting / waiting / ready / failed; full / delta; `lastError` = a reason code of `update_progress.REASONS` after a failure, logged once as `background update failed: <TypeName> (<code>)`; no `waiting` for a release that is already staged or held); with `resumable` (MainWindow) a game that starts mid-download keeps `<asset>.part` + `<asset>.part.json` (stable `browser_download_url`, sha256 digest, size) and the next run continues with `Range: bytes=N-` (only a 206 with exactly `Content-Range: bytes N-(size-1)/size` is appended; 200 / 416 / any other 206 restart from 0); the digest is always checked on the whole file and any failure other than a pause removes the partial file; logs `download: <bytes> B in <s> s (resumed from <N>)`, `verify: <s> s`, `extract: <s> s`; reused by `UpdateMessageBox` (not resumable). Windows delta (`Seraphine-<base>-to-<new>.delta`, `app/common/release_names.py`): `stageRelease(..., installDir=None)` tries it first only when the running version is exactly its base and it has a sha256 digest, the install dir is known (`installDir`, default `platform.install_dir()`), no restore is pending, ver.json's `noDelta` is not set and `update-fallback.json` has no `nodelta` entry for the version; download (resumable) → digest → extract → `Seraphine.exe` + `filelist.txt` + a usable `filemanifest.txt` (the precheck reads the `filemanifest.txt` **inside the downloaded, digest-verified delta package**; the install has none and the separate `Seraphine.filemanifest.txt` asset is not used) → `deltaFits` (Python mirror of the updater's step 4b, off the UI thread: every manifest entry the delta does not ship must match the installed file by size + SHA-256; an entry with a path segment ending in `.` or a space is refused) → marker `kind: delta` with the delta's digest, `base` (the running version) and `installDir` (normcased). Any delta failure except a cancellation logs `delta not used (<reason or type name>); staging the full package` and stages the full package in the same call; a deterministic failure (precheck misfit, missing / unusable manifest, digest mismatch, an archive that does not unpack or lacks its files; not HTTP / network / disk errors) also puts the version in `nodelta`. Paused downloads of both packages are kept while each matches its own resume key, so a misfitting delta never discards a paused full download. A delta-kind marker is used only by the version that staged it (its `base`; or the staged version itself, for the Retry of a half-applied run) on the install it was checked against: otherwise `stagedUpdate` removes it (a `failed:9` run of it still counts once for that version: two installs sharing a config dir share the count; nothing else is recorded), `markerApplicable` refuses it and `stagedFor` ignores it. `stagedFor` also ignores a staged delta once the release no longer publishes it, says `noDelta`, or the version is in `nodelta`, so the next update check replaces it with the full package. ver.json `noResume`: no `Range`, an earlier partial download is discarded. `<config>/update-fallback.json` (outside the stage dir, so `clearStage` and restarts keep it; written atomically, `os.replace` retried 3 times 0.2 s apart; unreadable or corrupt = empty, never raises; entries for versions not newer than the running one dropped at start-up): `nodelta` (any failed run of a delta-kind stage, or a deterministic delta failure while staging) and `failed9` (count of distinct `failed:9` runs per version, deduplicated by `result.json`'s `time`; when the file cannot be written, `result.json` stays and the run is counted at the next read). A `failed:9` result of any kind clears the stage so the next check downloads fresh; another `failed:<n>` of a delta stage clears it too (full package next); after `restored` / `restore-failed` a delta stage is kept and reported exactly like a full one (Retry bar, or the manual-download bar for restore-failed/8). Two distinct `failed:9` runs block that version (whatever its digest, until the running version moves past it): `failedRepair(v)` returns `{'lastResult': {'status': 'failed:9', 'code': 9, 'version': v}}`, `repairBlocks` is True for it (the manual-download bar, worded "This update does not match your install and could not be applied") and `stageRelease` raises `StageError("update blocked after repeated failures")` before any download (a pending result is counted first). After an updater run `package/` may be pruned (no longer equal to the asset) |

## For AI Agents

### Working In This Directory
- Prefer adding cross-component events to `SignalBus` over wiring direct references
  between `view/` interfaces.
- `config.py` is the single source for version strings and persisted settings — change
  versions here, not scattered literals.
- Theming is enum-driven (`Icon`, `StyleSheet`) and resolves against `../resource/qss/`
  (dark + light) and `../resource/icons/`.

### Testing Requirements
Pure-infra, covered by the unit tests (e.g. `test_update_stage.py`, `test_download_resume.py` (HTTP range resume, incl. a real 127.0.0.1 aiohttp server for the redirect), `test_update_progress.py` (progress states, throttle, phase-timing log lines), `test_update_progress_ui.py` (offscreen card / info bar wiring), `test_windows_updater_script.py`, `test_updater_partial.py` (manifest / delta / escape hatch / post-merge verify; legacy script snapshots in `tests/fixtures/legacy/`, kept LF by the root `.gitattributes`), `test_delta_staging.py` (delta selection table, injected delta failures falling back to the full package in the same call, paused downloads of both packages kept, the `deltaFits` precheck, stale delta markers, `update-fallback.json` across a simulated restart and with a failing write, the failed:9 loop bound, ver.json `noDelta` / `noResume`), `test_legacy_asset_pick.py` (the v1.4.6 and v1.4.8 pickers from `tests/fixtures/legacy/util_v1_4_*.py.txt` on the new asset list in all 24 orders),
`test_config_dir.py`). Run the suite from the repo root (`..\..` from here) with `QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -t .`
(`-t .` matters: it imports the modules as `tests.test_x`, so `tests/__init__.py` runs first and points the
config dir at a temp dir via `SERAPHINE_CONFIG_DIR`; without it the app is imported before that and the
run would read the real config, which `tests/test_config_dir.py` detects and fails on). Never launch the GUI to check a change: the offscreen unit tests and
`QT_QPA_PLATFORM=offscreen python main.py --version` / `--selftest` are the smoke tests.
`config.py` changes are smoke-tested by `QT_QPA_PLATFORM=offscreen python ../../main.py --version`.
`platform.config_dir()` honours a non-empty `SERAPHINE_CONFIG_DIR` environment variable on every platform
(used by the tests); anything that needs the config location must go through it.
